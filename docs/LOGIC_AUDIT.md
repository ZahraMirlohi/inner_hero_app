# تحلیل منطق برنامه و تصمیم‌ها

> نتیجهٔ خواندن کد (۱۳۱ فایل Dart، ~۷۲ هزار خط). همه چیز از روی کد است؛ ساختار جدول‌ها، RLS و توابع سرور دیده نشد.
> «تصمیم» = پیش‌فرضی که چون پاسخ نداده شد اعمال می‌شود. وضعیت: ✅ در مرحلهٔ ۱ انجام شد، ⏳ در مرحلهٔ بعدی.

## تصمیم‌ها (پیش‌فرض)
| موضوع | تصمیم |
|---|---|
| لغو تیک عادت | دقیقاً همان XP که داده شده برگردد؛ تیک مجدد/تغییر سطح همان روز فقط «تفاوت» را اضافه کند |
| هدیهٔ XP | انتقال از فرستنده به گیرنده با یک تابع سرور (اتمیک)، سقف روزانه ۱۰۰ XP |
| محاسبهٔ XP/استریک | سمت سرور (تابع SQL)، ستون‌های حساس فقط‌خواندنی برای کلاینت |
| استریک | اگر امروز هنوز انجام نشده، استریک تا دیروز نمایش داده شود؛ فقط با یک روز کامل خالی می‌شکند |
| تاریخ | بر اساس منطقهٔ زمانی تهران و ساعت سرور |
| تحلیل‌ها | سطح «نصفه» ۵۰٪ و «پایه» ۲۵٪ (مثل XP)؛ روزهای قبل از ساخت عادت و روزهای بدون برنامه شمرده نشوند؛ عادت‌های چالش/ماموریت دوبار شمرده نشوند؛ داده‌ی نمونه حذف و جایش حالت خالی |
| روزهای هفتگی | یک کدگذاری واحد (شنبه=۰ … جمعه=۶) و اصلاح داده‌های فعلی با SQL |
| بسته | XP فقط بار اول فعال‌سازی؛ حذف بسته بر اساس `package_id` |
| چالش | تکمیل‌شده دوباره XP نمی‌دهد؛ لغو/شکست XP روزهای انجام‌شده را برنمی‌گرداند (تصمیم ساده‌تر) |
| ماموریت | پیشرفت = تعداد «روزهای متمایز» |
| گروه | نقش‌ها: مالک، ادمین، عضو. کد دعوت، عمومی/خصوصی، گزارش، ممنوع/بی‌صدا |
| کانال | فقط ادمین پست می‌گذارد؛ واکنش استیکری فقط اگر مدیر فعال کرده باشد؛ هر کسی می‌تواند بسازد |
| آفلاین | ساخت/ویرایش/حذف عادت و کار هم آفلاین کار کند (UUID سمت کلاینت + صف) |
| تعارض داده | سرور برنده، به‌جز عملیاتی که هنوز در صف است |
| زبان | فارسی (طنز، بدون ایموجی) و انگلیسی (ساده) |
| بخش‌هایی که جدولشان نیست | پیام «به‌زودی»، بدون خرابی بقیهٔ برنامه |

## مشکل‌ها
### XP و استریک
1. ⏳ لغو تیک عادت همیشه XP کامل را کم می‌کند (حتی سطح پایه) — `today_tab.dart:630`, `sync_provider.dart:364`
2. ⏳ تغییر سطح همان روز XP تازه اضافه می‌کند — `supabase_service.dart:218-236`
3. ⏳ هدیهٔ XP از هیچ ساخته می‌شود و با باز شدن پروفایل پاک می‌شود — `buddy_chat_screen.dart:1989`, `xp_gift_service.dart:56-100`
4. ⏳ XP/استریک سمت کلاینت نوشته می‌شود؛ هر کاربر می‌تواند خودش را دستکاری کند
5. ⏳ XP در دو جدول (`user_progress`, `profiles`) با خواندن‌ـ‌نوشتن غیراتمیک
6. ⏳ استریک هر صبح تا انجام کار صفر می‌شود؛ تاریخ بر اساس ساعت گوشی
7. ⏳ فرمول سطح در چند فایل متفاوت (`profile_model` در برابر `character_model`)

### میدان (عادت/کار)
8. ⏳ خطای شبکه کش را پاک می‌کرد (`getHabits` در خطا `[]` برمی‌گرداند و ذخیره می‌شد) — ✅ در همگام‌سازی اصلاح شد (`getHabitsStrict`)
9. ✅ حذف آخرین عادت/کار از دستگاه دیگر هرگز به کش نمی‌رسید
10. ⏳ افزودن/ویرایش آفلاین خطا می‌دهد و داده را گم می‌کند
11. ⏳ شناسهٔ محلی با شناسهٔ سرور فرق دارد
12. ⏳ `_loadData` در تب امروز برای هر عادت دو درخواست پشت‌سرهم می‌زند و از ۸ جا صدا زده می‌شود
13. ⏳ روزهای عادت‌های هفتگی یک روز جابه‌جاست (`add_habit_screen.dart:59` در برابر `habit_model.dart:116`)
